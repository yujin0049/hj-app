# 계획 달력 · 현황표 — Concept (v01, 2026-10-21)

## 목적
유진님이 한눈에 「오늘 무엇을, 언제까지, 누가」를 보는 업무 대시보드. 연습장(hj-app) 안의 두 화면.

## 화면
1. **계획 달력** (`#/calendar`)
   - 월 보기 / 주 보기(일요일 시작) 전환, 이전·다음·오늘 버튼.
   - 두 줄(레인)을 섞지 않음: 「유진님 할 일」(파랑) · 「교수님 일정」(보라). 레인 켜고 끄기.
   - 「다가오는 일정」 목록: D-day, 마감 임박(D-3 이내, 주황), 지연(마감 지남·안 끝남, 빨강), 끝남(회색).
   - 거르기: 담당 봇 · 상태 · 업무 분야 · 끝난 일 보기.
2. **현황표** (`#/status`)
   - 맨 위 「유진님이 하실 일」 고정 칸: 대기: PC · 대기: KORUS(회계 시스템) · 결재·상신 · 확인 필요 · 유진님 직접.
   - 아래 전체 표: T번호, 업무 이름, 상태, 마감(D-day), 담당 1봇. 같은 거르기.
   - OJNT 서류 진행률(숫자와 비율만, 이름 없음).
3. **모든 화면** 위에 「마지막 갱신 YYYY-MM-DD HH:MM (KST)」. 갱신 실패 또는 24시간 넘게 안 바뀌면 빨간 경고 띠.

## 자료 (정본)
- **업무(할 일)·상태의 정본 = 인수인계봇 현황판 시트 '업무' 탭**(공지 261021 규칙 1). 사이트는 **읽기만**. 고치는 곳은 현황판뿐.
- **일정의 정본 = 대장의 `00 홈/일정총괄.json`**(공지 261021-7·8, build_schedule.py). 있으면 자동으로 읽음. 모양이 달라도 날짜·제목·T번호·구분 칸을 찾아 씀. 모르는 칸 이름은 `/workspace/hj_audit/calendar/일정총괄_모르는칸.txt`에 적음. 대장이 단 충돌 표시는 「충돌」로 보여 줌.
- `data/calendar_extra.json` = 일정총괄에 아직 없는 대장 고정 일정만. 같은 날·같은 T번호·같은 레인이면 일정총괄이 먼저(extra 는 빠짐).
- 통합 자료 `/workspace/hj_audit/ingest/통합일정.json`·`통합할일.json`(구글 캘린더·노션, 다른 작업자) = 나머지를 보탬. 같은 T번호 할 일은 현황판이 정본이라 날짜가 다르면 「충돌」만 표시. T번호·제목+날짜로 중복 제거.
- 날짜가 서로 다르면 「충돌」, 그 밖에 애매하면 「확인 필요」.
- 업무 분야 묶음(거르기): OJNT · 특강 · 강사료 · 실습재료 · 행사 · 사물함 · 공문 · 기타.
- OJNT 진행률 = OJNT 시트 '입사서류체크' A2 요약 줄(시트 수식) + 줄 세기로 맞춰 보기. 숫자만.
- 「교수님 일정」 Google 캘린더는 다른 작업자가 만드는 중(10.21.). 생기면 통합일정으로 들어옴. 그 전에는 교수님 레인 = 일정총괄의 특강 강의일. 제목은 일반 제목만(예: 「교수님 출장」), 이름은 스크립트가 지움.

## 갱신 (빌드 때 자동 읽기)
- 사이트는 정적 파일이라 비공개 시트를 **실시간으로 읽지 못함**. 대신 정해진 때 봇이 커넥터로 시트를 읽어 원자료를 박스(`/workspace/hj_audit/calendar/`, 권한 600, 저장소 밖)에 두고 → `tools/refresh_all.py`가 `data/*.json`을 다시 만들고 → 미리보기 워커를 다시 배포.
- 손으로 옮겨 적지 않음. 다시 돌리면 = 갱신.
- 주기(예: 평일 매시)는 대장이 정함. 방법: `/workspace/hj_audit/calendar/갱신방법.md`.

## 개인정보
- 사이트에는 업무 이름·날짜·상태·분야·담당 봇만. 사람 이름·전화·계좌·주민번호·이메일 없음.
- 업무 이름 안의 사람 이름은 스크립트가 지움(「OOO 교수님」→「교수님」). 모든 출력 파일을 `tools/cal_pii_check.py`가 검사, 걸리면 종료 코드 2로 멈추고 배포 안 함.
- 원자료(시트 덤프)는 저장소에 넣지 않음.

## 접근 (10.21. 10:00 유진님 결정 변경)

- 저장소·`data/*.json`에는 **개인정보 0** 그대로(잠금이 풀리거나 GitHub 저장소가 공개라도 새지 않게).
