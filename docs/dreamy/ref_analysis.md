# 참고 사이트 분석 — dreamy-semolina

- 대상: https://dreamy-semolina-6aea11.netlify.app/
- 조사일: 2026-11-16 (Asia/Seoul)
- 방법: curl로 HTML·응답 헤더 확인, 추가 경로 조사, headless Chrome 1280·390 화면 확인
- 목적: 구조·기능·화면 흐름을 적고, hj-app 안의 같은 도구(#/office-guide) 1차 구현의 근거로 씀

## 한 줄 요약

로그인·서버·다른 주소 없이, **한 장의 정적 HTML**로 된 「신입사원 필수 업무 가이드」다. 화면은 **1개**, 본문은 **10개 쪽(섹션)** 으로 나뉘고, 왼쪽(좁은 화면에서는 위) 목차로 이동한다. 할 수 있는 일은 **목차 이동 · 인쇄/PDF 저장 · 주소 복사** 뿐이고, 체크리스트는 글자 □ 일 뿐 누르는 칸이 아니다.

| 항목 | 내용 |

## 화면 목록 (1개 화면, 10개 쪽)

원본은 라우트가 하나다. 「화면」이 아니라 같은 페이지 안의 `section#page1` … `#page10` 이다. 본문 장 번호는 **01→02→03→04→05 다음이 07** 로, **06번 장이 없다**(원본 그대로). 목차 번호(01–10)와 장 번호는 다르다.

| 쪽 | 목차 제목 | 주요 내용 | 입력 | 출력 |
|----|-----------|-----------|------|------|
| 1 | 01 · 직급과 호칭 | 도입 + 장 01 직급 호칭·직급/직책 | 없음 | 정적 안내, 직급-호칭 표 |
| 2 | 02 · 전화 응대 | 호칭 꿀팁 + 장 02 전화 멘트 ①–⑥ + 메모할 항목 앞부분 | 없음 | 멘트·목록 |
| 3 | 03 · 전화 메모·메신저 | 메모 항목 나머지, 메모 자리표시 예시, 전화 꿀팁, 장 03 메신저 ①② | 없음 | 템플릿 |
| 4 | 04 · 메신저·메일 | 메신저 ③–⑤·꿀팁, 장 04 메일 구성 1–4 | 없음 | 템플릿 |
| 5 | 05 · 이메일 예시 | 메일 구성 5–8, 메일 예시 ①–④ 앞 | 없음 | 템플릿 |
| 6 | 06 · 업무 노트 | 메일 ④ 끝·꿀팁, 장 05 업무 노트 ①② | 없음 | 안내·순서 |
| 7 | 07 · 업무 노트 실전 | 노트 ② 끝, ③ 폴더 경로, ④ 마감일, ⑤ 담당자 앞 | 없음 | 안내 |
| 8 | 08 · 업무 노트 정리 | 담당자 자리표시, ⑥ 주의, ⑦ 물음표, ⑧ 재정리 목차 | 없음 | 안내 |
| 9 | 09 · 단축키·첫 출근 | 장 07 추가 꿀팁 5가지, 첫 출근 체크리스트 1–5 | 없음(□는 글자) | 목록 |
| 10 | 10 · 체크리스트 | 체크리스트 6–10, 맺음말 | 없음(□는 글자) | 목록·응원 |

**화면 수: 1. 쪽 수: 10. 장 수: 5개(01–05) + 07(06 없음) + 체크리스트·맺음말.**

쪽을 가르는 기준은 주제의 끝이 아니라, 대략 한 화면에 들어가는 길이인 것으로 보인다. 같은 장이 여러 쪽에 걸친다.

## 기능 목록

| # | 기능 | 동작 | 비고 |
|---|------|------|------|
| 1 | 히어로 | 작은 제목 `OFFICE STARTER GUIDE`, 제목, 한 줄 소개 | 정보만 |
| 2 | 목차 | 10개 링크 `#page1`…`#page10`. `html { scroll-behavior:smooth }` | 데스크톱은 `sticky` |
| 3 | 인쇄 / PDF 저장 | `window.print()` | 브라우저 인쇄 대화상자. 서버 PDF 변환 없음 |
| 4 | 현재 페이지 주소 복사 | `navigator.clipboard.writeText(location.href)` 성공 시 알림, 실패 시 「주소창에서 링크를 복사해 주세요」 | 해시(`#pageN`)가 있으면 그 주소가 복사됨 |
| 5 | 첫 출근 체크리스트 | 10개 항목, 글자 `□` | CSS에 `.check input` 이 있으나 HTML에는 `input`이 없음. **누르는 체크박스가 아님** |
| 6 | 로그인·계정·결제·저장·검색·수정 | 없음 | 서버·쿠키·localStorage 없음 |
| 7 | 다른 언어·다크모드 | 없음 | |

**기능 수: 실제 동작 4개(목차 이동, 인쇄, 주소 복사, 스크롤) + 보이는 체크리스트(비대화형).**

## 데이터 입출력

- **입력:** 사용자 자료를 받지 않는다. 폼·업로드·검색창 없음.
- **출력:** 화면에 고정 안내문·템플릿을 보여 준다. 인쇄는 브라우저가 하고, 주소 복사는 클립보드만 쓴다.
- **빈 자료:** 원본은 항상 본문이 채워져 있다. 빈 목록 화면은 없다.
- **개인 소개:** 원본 1쪽 도입에 작성자 1인칭(특정 업종·연령 표현)이 있다. 재구현에서는 이 소개를 넣지 않고, 안내 목적의 문장만 둔다.
- **자리표시:** 호칭·멘트·메일 보기에는 `OO`, `○○`, `OOO` 같은 빈칸만 쓴다. 재구현에서도 실명·실제 전화·이메일은 쓰지 않는다. 연락처 보기는 숫자 대신 가린 자리만 둔다.

## 화면 흐름

```
진입 (/)
  └ 히어로(제목 + 인쇄 + 주소 복사)
      └ 목차 10개 + 본문 10쪽 (한 페이지에서 아래로 이어짐)
          ├ 목차 클릭 → 같은 문서의 해당 쪽으로 스크롤
          ├ 인쇄 / PDF 저장 → 브라우저 인쇄(목차·도구 숨김)
          └ 주소 복사 → 알림 후 그대로 읽기
체크리스트는 흐름의 끝이지만, 눌러도 상태가 바뀌지 않는다.
뒤로 가기 계층·다음 화면·모달은 없다.
```

## 재구현 때 맞출 것 (1차)

1. hj-app 안 새 화면 `#/office-guide`. 새 앱·live(main, GitHub Pages)는 열지 않음.
2. 같은 10쪽 목차·같은 장 구성(06번 장 없음도 유지).
3. 인쇄, 주소 복사, 목차 이동.
4. 브랜드 C: 강조색 `#4CC3FF`, 글꼴 Hahmlet. 원본의 청록 팔레트는 베끼지 않음.
5. 자료가 비면 「데이터 없음」. 본문은 안내 템플릿이며 예시 학생·직원 자료를 만들지 않음.
6. 체크리스트: 원본은 글자 □ 뿐. 1차에서는 실제로 체크할 수 있게 하되, 이 기기 `localStorage`에 항목 id만 저장(이름·연락처 없음).
7. 쪽 안 이동은 `#/office-guide/p1` … `/p10` (앱이 해시 라우트라 원본의 `#pageN` 을 그대로 쓰면 화면이 바뀜).

## 이 문서의 한계

- 원본은 공개된 정적 페이지라 로그인 뒤 화면은 없다(추가 경로 404).
- CSS에만 있고 안 쓰는 선택자(`.check input`)는 「만들다 만 흔적」으로 보았고, 숨은 API는 없다.
