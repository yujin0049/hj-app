## 「main 에 이미 있는 파일은 건너뛰기」 를 넣은 뒤
- 구현: `--main <ref>` 에서 head 의 파일 내용(blob)이 main 과 같으면 그 파일은 안 봄. CI 는 `--main <base sha>`. 합성 s09 로 확인.
- 실 PR 재생(main = 그 PR을 검토·머지할 때의 main): **변화 없음** — caught 29/29 · missed 0 · findings 30 · FP 1 (3.3%).
- 이유: 0012_rev_index.sql 은 PR#17 때 main(38166f0)에 **없었음**. PR#17 은 ba421e6(부모 38166f0, 내용 = 116d7c4)로 squash 머지됐고 0012 는 그때 처음 들어감. 그래서 「main 에 이미 있음」 으로 걸러지지 않음.
- 참고(잘못된 재생): main 을 지금 main(e864f25)으로 두면 0012 는 빠지지만 머지된 PR 의 다른 파일도 다 빠짐 → caught 10/29 · missed 19 · FP 0. 쓰면 안 되는 기준.

## 0012 지적이 정말 오탐인가
- 지적 내용: 「실 D1에 적용하는 migration 머리말에 유진님 OK 문구 없음」(R6 주의).
- 같은 모양인 0016_gsync.sql(더하기만, 머리말에 OK 문구 없음)은 처음부터 정답(TP)으로 적었고, 0012 는 적지 않았음 → 규칙이 아니라 **정답표가 서로 다름**.
- 표는 엄격하게 그대로 둠(0012 = FP). 0012 를 0016 과 같이 TP 로 보면 FP 0 (0%).
- 진짜로 0012 를 빼고 싶다면 규칙을 「더하기만(CREATE … IF NOT EXISTS·트리거) 파일은 OK 문구 검사 제외」로 바꿔야 하는데, 그러면 0016 도 같이 빠짐. 결정은 춘식이 몫으로 남김.
